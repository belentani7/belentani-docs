# Arquitectura del Ecosistema Belentani

## Visión General

El ecosistema Belentani está compuesto por **8 proyectos flagship** que comparten infraestructura común: Design System, template Python, servidores MCP, y portal de documentación unificado.

## Principios Arquitectónicos

### 1. Clean Architecture (Backend)
- **Dominio independiente**: Sin dependencias de frameworks
- **Adaptadores intercambiables**: DB, HTTP, Queue, Auth
- **Contratos explícitos**: Protocolos Python para puertos
- **Fallos controlados**: Errores como valores, no excepciones

### 2. Design System First (Frontend)
- **Tokens centralizados**: Colores, spacing, motion, shadows
- **Componentes compuestos**: Card, Dialog, Select, DropdownMenu
- **Accesibilidad nativa**: Radix UI primitives
- **Dark/Light mode**: CSS custom properties

### 3. Observabilidad por Diseño
- **OpenTelemetry**: Tracing, métricas, logs estructurados
- **Health checks**: /health, /ready en todos los servicios
- **Rate limiting**: Por IP, configurable por endpoint

## Flujos de Datos

### CI/CD Pipeline
```
push/main → GitHub Actions → lint → typecheck → test → build → deploy preview → review → merge → deploy prod
```

### Deploy Strategy
- **Vercel**: Frontend (Next.js, Vite, Static)
- **Railway/Fly.io**: Backend APIs (FastAPI)
- **GitHub Pages**: Static sites (Cruzando, Secure T)

### Branch Protection
- Requerido: build, typecheck, test, lint
- 1 approval mínimo
- Linear history
- Admin enforcement

## Seguridad

- **Gitleaks**: En todos los repos
- **Dependabot**: Grouped updates, major ignores
- **CODEOWNERS**: @belentani7 review required
- **Secrets**: Solo en Vercel/GitHub secrets, nunca en repo
- **Rate limiting**: Middleware configurable

## Observabilidad

- **Structlog**: JSON logs estructurados
- **OpenTelemetry**: Tracing distribuido
- **Health endpoints**: /health, /ready
- **Metrics**: Prometheus-ready
